Especificação da Comunicação M2M • Gateway LoRa ↔ MQTT

Referência técnica embarcada (declara_componentes.h, M2M.ino, rede_lora.h e setup.ino)

1. Broker MQTT & Credenciais
• Servidor: 163.176.56.133:1883 (TCP direto)
• Usuário / Chave: wbm_technology / Wbm.technology01
• Padrão Control Flow: Mestre_<MAC_12_HEX>_CF_<N>
• Sincronização Lovable: Usada apenas para Nome e Local do dispositivo.
2. Filtro Anti-Fantasma (Slots LoRa)
• O Gateway Mestre varre slots LoRa e publica md=0, er=7 para endereços sem válvula física conectada.
• O servidor filtra automaticamente esses slots vazios e só auto-descobre válvulas reais que respondam com modo válido (md=1 ou md=2) ou ACK 2 / 3.
3. Estrutura de Tópicos e Handshake de Confirmação (Status "1", "2" e "3")
• Válvulas Control Flow: devices/Mestre_<MAC>_CF_<N>/telemetry | /status | /cmd
• Status "1": Comando JSON recebido pelo Mestre via MQTT → Agenda 3x LoRa + 3x Telemetria MQTT.
• Status "2": Válvula confirmou via LoRa que seu setpointManual interno igualou o setpoint enviado.
• Status "3": Válvula confirmou via LoRa que sua posição física (po) atingiu o setpoint desejado (sm).
